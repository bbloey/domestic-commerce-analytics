要说明什么举例说明不说明会怎样
① 数据契约例如：一个订单买了两种商品，会有两条明细，但仍只算一个订单；金额单位是人民币元。把订单明细行当人数，或把不同粒度的度量直接相加
② 指标口径例如：模拟月GMV为10万元、全店目标为20万元，目标达成率为50%；净收入不等于利润。同名指标含义不同，KPI与表格对不上
③ 章节骨架例如：先看总览发现销售下降，再到产品和渠道页找下降贡献，最后核查数据质量。只有图表，没有从问题到证据的分析过程
④ 输出约束例如：选择“京系”后渠道图只看京系；指标定义保持不变，不支持渠道筛选的模块要明确提示。筛选看似变化却未重算，或固定结论随筛选失去依据

RFM分档与分群

历史截至所选月末，R由久到近、F/M由低到高分别按NTILE(5)规则分为1—5档；同值按客户ID打散，可能分属邻档。客户不足5人时不保证出现5分。

按以下顺序互斥归类：R≥4且F≥4且M≥4→高价值忠诚；R≥3且F≥4→忠诚；R≥4→新近高潜；R≤2且M≥4→沉睡高价值；R≤2→流失风险；其余→一般客户。这里的R/F/M条件指分档得分，不是原始天数、订单数或金额。这是教学规则，不是预测概率。

排除与空值

必填缺失、唯一键重复、计数非法、退货超过购买等情况拒绝整次更新，不静默删行。流量组合不完整时隐藏相应转化图并提示补充。分母为0或上月缺失时底层返回空值；现有部分图形仍可能将空值画为0，不能据此声称实际值为0。

不含成本、投放和匹配退款批次，不能回答利润、ROI、真实退款率或增长原因；模拟平台对比不能用于判断真实平台优劣。

④ 输出约束哪里联动、如何重算、交付什么、怎样验收

固定层与联动层

固定层：章节顺序、指标定义、阈值、业务边界、页尾学习声明。版本层：本页样本量与数据范围、完整版本的覆盖和客户质量统计。联动层：各图表仅按上表支持的筛选重算；界面显示忽略的筛选项。经营总览选择渠道时，缺少对应口径的订单数、净收入等显示空值；全店客户卡仍只随月份变化。

结构与数字

按本项目已定义的六个模块一一对应组织，不在换数据时随意删减；不是对其他网站全部业务口径作1:1承诺。输入金额来自明细或月目标表，聚合数由计算产生，不能把KPI写死在页面。比例由汇总分子÷汇总分母重算，去重人数不能跨分组直接相加。

更新流程

上传文件或SQL查询 → 选择表与字段映射 → 预览/编辑草稿 → 校验 → 版本检查 → 应用整张表 → 后端重算 → 页面刷新。查询和编辑草稿不会直接覆盖看板；新增月份先补目标。完整服务支持撤销上一次更新。

交付物

本地完整网站、独立HTML报告、三表CSV/Excel样例、分析与服务源码、月度指标CSV、质量审计JSON、数据口径文档和GitHub源码包。GitHub Pages仅支持静态展示与已有数据筛选；上传、SQL和编辑需要Python服务。构建默认读取 data 中的CSV，不读取本机上传版本，因此公开报告不自动同步本机更新。

验收清单

  • 同月同范围的总览、产品、SKU、渠道与小时GMV回汇总一致。
  • 一单多行不增加订单数；客户频次分布人数之和等于当月客户数。
  • 切换月份/渠道后，仅支持该筛选的模块重算；固定定义和范围提示保持明确。
  • Excel/CSV往返、字段校验、版本冲突、撤销、只读SQL正常。
  • 公开HTML包含全部说明，图表正常显示；不包含本地运行状态或数据库凭据。
