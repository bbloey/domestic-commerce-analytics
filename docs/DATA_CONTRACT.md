# 数据口径与质量规范 · Domestic Commerce Analytics

本文件定义当前国内电商学习报告的字段、指标与质量规范。它与UCI项目的客户分群和复购口径不同。

## 1. 数据范围与模型

默认公开数据：固定种子20261116生成2026年1—4月模拟业务；6个产品、12个SKU，抖系/淘系/京系三个互斥订单渠道，3,450条订单商品行。人民币元（CNY）金额为行合计，不是单价；源时间按北京时间（UTC+8）解释，文件中不带时区。

| 表 | 粒度/唯一键 | 全部必需字段 |
|---|---|---|
| orders | 每条订单商品行；line_id唯一；一订单可多行 | line_id、order_id、order_date、customer_id、product、sku、channel、quantity、returned_quantity、gmv_cny、net_sales_cny |
| traffic | 月份×产品×渠道 | month、product、channel、impressions、page_views、unique_page_views、unique_customers |
| targets | 月份 | month、target_gmv_cny |

订单line_id必须唯一；order_id可重复，但对应的客户、订单时间、渠道一致；同一SKU只能属于一个产品。缺客户ID的订单不能直接导入此模板，需先设计匿名口径，不能随意伪造真实客户身份。模拟客户ID仅用于演示。

## 2. 计算与筛选

| 指标 | 公式/解释 |
|---|---|
| GMV | SUM(gmv_cny)，按order_date月份归集；不自动判断付款/完成状态，需由导入者定义 |
| 净收入字段合计 | SUM(net_sales_cny)；这是外部提供字段，不是本项目与结算账单匹配计算的净收入，不等于利润 |
| 购买件数 | SUM(quantity) |
| 净销量 | SUM(quantity)−SUM(returned_quantity) |
| 订单数 | 当前统计范围内COUNT DISTINCT(order_id)，一单多行不能重复计数 |
| GMV达成率 | 当月GMV÷当月target_gmv_cny；目标为0时底层不可计算 |
| 环比 | 当前月÷紧邻上一月−1；上期为0/缺失时不可算，不跳过空月 |
| 渠道GMV占比 | 当前渠道GMV÷所选范围三个渠道GMV合计；本地订单渠道互斥 |
| CTR（浏览曝光比） | Σpage_views÷Σimpressions；当前traffic没有clicks字段，**并非严格搜索点击率** |
| CVR代理 | Σunique_customers÷Σunique_page_views；跨产品的去重数相加是产品范围次数，不代表全渠道重新去重的人数 |
| 件数退货率 | Σreturned_quantity÷Σquantity；导入字段口径下的件数比例，不是退款金额率 |
| 回头客率 | 当月客户与此前已出现客户的交集人数÷当月客户数；不是月内购买≥2次比例 |
| 月购买频次 | 每客户当月去重订单数；分为1、2、3、4、5次及以上 |
| 人均消费/购买频次 | 当月GMV或净收入/订单数÷当月客户数 |

产品页产品销量采用购买件数gross_items；总览与SKU净销量采用扣退货后的net_items。两个概念须按图表标签理解，不能误认为数值必然一致。

筛选范围：总览按月/商品/SKU/渠道允许的组合计算；产品页只接受月/产品/SKU，忽略渠道；渠道页接受月/产品/渠道，忽略SKU；客户页和质量页只接受月份。界面会提示不适用的筛选项。选择渠道时总览缺少独立计算的数据如净收入、订单数展示空值，不冒充全店值。

目标为月度全店目标，并未提供SKU级目标分摊。跨产品订单和客户数不能通过分组数相加恢复全店去重数量。

## 3. RFM规则

历史窗口：最早订单月至所选月；月末作为观察日期。R=月末距最后购买的天数；F=截至月末去重订单数；M=截至月末net_sales_cny合计。

每项按SQL NTILE(5)方式分成1—5档，余数分配给前面的档。同值使用customer_id排序打散，因此边界相同值可能分属相邻档。R由久到近排序，F/M由低到高排序，5分为高值。少于5个客户时不保证最大分到5。

分群顺序互斥：R≥4且F≥4且M≥4→高价值忠诚客户；R≥3且F≥4→忠诚客户；R≥4→新近高潜客户；R≤2且M≥4→沉睡高价值客户；R≤2→流失风险客户；其他→一般客户。阈值是本地演示规则，不是平台官方业务规则，也不是流失概率。

客户Top200按累计净收入字段合计排序。未观察到更早购买历史，因此“首次出现”并不等于真正新客。

## 4. 质量门槛

所有表每次最多20,000行。必需字段不能空；数字必须有限、非负；计数为整数；quantity>0且returned_quantity≤quantity；月份YYYY-MM；订单时间可解析且无时区；金额单位固定人民币元（CNY），不接受外币直接混入。channel仅接受douyin（抖系）、taobao（淘系）、jd（京系）。

流量约束客户≤去重浏览≤浏览≤曝光是**此模板要求**，不是任何平台都自然满足的规则。实际来源不满足时需重新定义入口/人群和统计窗口，不能强行改数。

orders非空且跨度不超过60个月。按首末月补齐连续月份（空月GMV为0）；targets必须覆盖全部月份，包括中间空月。新增月份先补目标，再应用订单。

traffic不完整时保留订单分析，并提示流量不完整；不能从GMV推算曝光或转化。导入前不自动删重复或填未知值，校验不通过拒绝整个更新。

## 5. 对账、更新与边界

验证总览、产品、SKU、渠道、小时GMV回汇总一致；订单多行不增加订单数；客户频次分布人数之和等于当月客户数。公开生成器写入`output/quality_audit.json`。

发布版更新流程：修改data目录中的三张CSV → 执行python build.py → 全表校验 → 指标聚合与对账 → 重新生成HTML和输出文件。任一步失败不应发布新结果。完整网站保留Excel/CSV上传、SQL、在线编辑、校验后应用和撤销后端；运行start.cmd后使用。

后端零分母返回null；部分前端辅助函数将空值显示为0，解释时须结合缺失提示，不能把所有可视化0都当作观测到的0。金额使用浮点后端汇总并保留6位，展示保留2位，不作为财务账本。

模拟流量和目标均非真实经营观测；无成本、费用或广告投入，不计算利润/ROI。默认构建读取本副本data目录中的学习模拟数据，不读取其他项目或本机运行状态。数据映射覆盖率100%是导入校验结果，非证明原始业务数据完美。

## 国内版学习声明与渠道身份

模拟数据，非真实数据，仅供学习。抖系（douyin）、淘系（taobao）、京系（jd）仅为三个互斥的模拟平台来源；每条订单只属于其中一个渠道，不代表任何平台的官方口径或真实业绩。

客户编号为本地生成的模拟统一ID。真实跨平台数据不能假定同名或同号即为同一人，复用前须有合法且可靠的身份映射；否则应按平台分别统计客户。流量为统一教学定义，不保证各平台后台同名指标可直接比较。

金额字段使用gmv_cny、net_sales_cny、target_gmv_cny。国内版重新生成模拟人民币价格与目标，并非汇率转换；旧版外币模板不能直接导入。国内版仅需orders、traffic、targets三表。
